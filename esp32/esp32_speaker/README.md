# ESP32 Speaker Node for Sensor Playground

An **actuator** node: the Sensor Playground app plays tones and a built-in
melody on a
[Grove Speaker](https://wiki.seeedstudio.com/Grove-Speaker/) wired to the
ESP32, and the node reports what is actually sounding back.

> **A two-way node.** Like the LED and the TM1637 clock this node both
> consumes commands and reports state. A tone ends on its own when its
> duration runs out — the node publishes the resulting silence, so the
> app's card follows the node rather than the tap.

The square wave is generated by the ESP32's LEDC peripheral; the Grove
module's onboard transistor amplifies it. No sensor library is needed.

## Protocol

- **UDP Discovery (port 9133):** Responds to `SENSOR_TESTER` broadcasts
  with a JSON identity packet (`type: "SPEAKER"`, host, ip,
  `port: 9132`). The app recognises the type and opens the speaker
  screen.
- **WebSocket (port 9132, `ws://`):** The client presents the shared
  `X-Api-Key` header on the handshake. Both directions are text messages:

  | Direction | Message | Meaning |
  |-----------|---------|---------|
  | app → node | `{"tone":{"freq":440,"ms":400}}` | play one tone |
  | app → node | `{"melody":true}` | play the built-in melody |
  | app → node | `{"stop":true}` | silence |
  | node → app | `{"freq":440}` / `{"freq":0}` | what is sounding — sent once right after connect and on every change, including a tone ending on its own |

> This node uses plaintext `ws://` (not `wss://`), consistent with the
> other actuator nodes (LED, SSD1306 display, TM1637 clock).

## Transport (compile-time switch)

| `ACTIVE_TRANSPORT` | Behaviour |
|--------------------|-----------|
| `TRANSPORT_WIFI` | WebSocket server (9132) + UDP discovery (9133). |
| `TRANSPORT_BLE`  | BLE GATT service; the app writes the API key to the auth characteristic, subscribes to the data characteristic for the state and writes commands to the command characteristic. |

Over BLE the state notify carries the same `{"freq": …}` JSON, but a
command is a short binary write (BLE writes are binary-safe):

| Packet | Meaning |
|--------|---------|
| `0x01 <freq:u16 BE> <ms:u16 BE>` | play one tone |
| `0x02` | play the built-in melody |
| `0x03` | silence |

## Hardware

- **ESP32** (e.g., NodeMCU, DevKit v1)
- A Grove Speaker — https://wiki.seeedstudio.com/Grove-Speaker/
  (a Grove Buzzer works too, at reduced sound quality)

### Wiring

| ESP32 Pin | Grove Pin |
|-----------|-----------|
| 5V (or 3.3V) | VCC (red) |
| GND | GND (black) |
| `SPEAKER_PIN` (default GPIO 5) | SIG (yellow) |

> The module is louder at 5V; the SIG line only carries the ESP32's
> output, so either supply is safe.

## Configuration

Set these at the top of the sketch:

| Define | Default | Meaning |
|--------|---------|---------|
| `SPEAKER_PIN` | `5` | GPIO driving the speaker. |
| `MELODY` | C-major fanfare | The built-in melody's (freq, ms) steps. |

Then copy `secrets.h.example` to `secrets.h` and fill in WiFi + API key.
`secrets.h` is excluded from Git. This node has no HTTPS endpoint, so no
TLS certificate is needed.

## Software Requirements

1. **Arduino IDE** or **VSCode with PlatformIO**
2. **Board Support**: ESP32 by Espressif (core 3.x — the sketch uses the
   `ledcAttach` / `ledcWriteTone` API)
3. **Libraries** (Library Manager):
   - `ArduinoJson` by Benoit Blanchon
   - `WebSockets` by Markus Sattler (links2004/arduinoWebSockets)

### Quick install (arduino-cli)

Instead of the manual IDE setup above, you can build and flash with
[arduino-cli](https://arduino.github.io/arduino-cli/) using the bundled
script:

```bash
./install.sh <serial-port> [WIFI|BLE]

# Examples
./install.sh /dev/cu.usbserial-0001        # BLE (default)
./install.sh /dev/cu.usbserial-0001 WIFI   # Wi-Fi
```

The script installs the ESP32 core and all required libraries, creates
`secrets.h` from `secrets.h.example` on the first run (edit it, then
re-run), compiles the sketch with
`-DACTIVE_TRANSPORT=TRANSPORT_<WIFI|BLE>`, and uploads it to the given
serial port. Watch the serial log afterwards with:

```bash
arduino-cli monitor -p <serial-port> --config baudrate=115200
```

## Testing

With [`websocat`](https://github.com/vi/websocat):

```bash
websocat -H='X-Api-Key: your-sensor-api-key' ws://<esp32-ip>:9132/
```

The current state prints on connect. Type
`{"tone":{"freq":440,"ms":1000}}` and press enter — the speaker sounds an
A for one second and the node echoes `{"freq":440}`, then `{"freq":0}`
when the tone ends.
